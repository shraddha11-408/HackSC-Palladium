CPU intake stays online during a running heavy job. A newly connected phone
continues to buffer and receive ACKs while its analysis is visibly queued.
The GPU Pod's included CPU resources run this plane; no extra CPU server exists.
Stopping this Pod stops the API, live inference and media access. The Replit UI
stays reachable but disconnected. A separate API host is a later deployment
choice if GPU-independent backend uptime is required.

Network and storage boundaries
------------------------------
Public API: container port 8000, behind the owner-approved Runpod HTTPS proxy.
MOSS: 127.0.0.1:18001 only; its unauthenticated protocol is never public.
Reviewer access: owner-only data/app_token; cookie is Secure + HttpOnly.
Phone access: one-hour random pairing token in /capture#fragment, first WS message.
Mac: source backup + provider API keys + conservative local spend/stop guard.
Worker: HF download token + Supabase archive secret; no Runpod/Vultr admin key.
data/uploads/: exact uploaded bytes, read-only and SHA-256 hashed.
data/incidents/: originals and separately named derived review artifacts.
data/safesc.db: sources, jobs, provenance and append-only reviewer actions.
weights/ and third_party/: downloaded checkpoints and pinned model environments.

Phone details
-------------
The phone uses getUserMedia, not RTSP or a special mobile app. HTTPS is required
outside localhost. The phone and reviewer can be on different networks.
Frame ACK pacing is bounded; actual FPS is measured, not promised as 8 FPS.
Camera JPEGs are authoritative received input, not lossless sensor originals.
Incident MP4s are timestamp-preserving encoded derivatives. Exact uploads stay intact.
Keep the page foregrounded and phone awake. Reconnect starts a new stream clock.
Physical-device camera permission still needs the owner's iPhone/Android check.

Learning and forecasting boundaries
----------------------------------
IMPLEMENTED: distinct observer/verifier roles, serialized artifact workers,
reviewer-only notifications, raw-response provenance, human feedback export.
NO automatic weight training, self-label training, or automatic prompt changes.
Human decisions are judgments, not independent ground truth.

PLANNED: CPU forecasting of REPORTED incident counts by area/time, chronological
held-out evaluation, and forecast layers on the activity map. Forecasts never increase a video's
evidence score, identify people, or disable observation of lower-ranked areas.
Any future tuning requires reviewed labels, a held-out test and an approved release.

Unavailable: OneStreamer weights. MOSS remains the deployed streaming observer.
Multiple simultaneous live feeds are not claimed by this single-session prototype.

Historical activity plane (implemented; independent of video inference)
----------------------------------------------------------------------
Official LAPD 2010-19 + 2020-24 + NIBRS public datasets
  -> whitelisted fields + small server-side bounding box
  -> compressed local raw pages + hashes + query manifests
  -> published UPC Lyft polygon filter + exact-case grouping
  -> data/activity/activity.sqlite (read-only application queries)
  -> authenticated date-range / points / detail APIs
  -> Campus activity tab: orange recency circles + calm source-linked summaries

The master snapshot remains on the Mac; a minimized copy is on Runpod.
Map tiles come from OpenStreetMap with attribution, without paid API keys.
No victim demographics, precise addresses, danger scores or forecasts are shown.
The current digitized boundary is approximate and applied to all archive years.

Reviewed learning branch (implemented research prototype)
--------------------------------------------------------
Permitted confirmed incidents / separately uploaded missed events
  -> retained original + permission history + visible interval annotation
  -> immutable grouped train / validation / test manifest
  -> isolated Qwen LoRA optimization (MOSS weights unchanged)
  -> held-out evaluation + artifact hashes + original inputs in the UI
  -> automatic gate OR explicit hash-bound owner research approval
  -> research-labeled verifier adapter, with human review still required

The first pilot uses 19 research training windows. Automatic promotion failed
because false alerts increased; the owner approved the high-recall staged demo.
No continuous self-training, institutional approval or zero-miss claim is made.

Private archive (independent CPU/network worker, no extra GPU)
-------------------------------------------------------------
Original incident + thumbnail + versioned review JSON -> private Supabase bucket.
800 MiB managed cap: evict oldest archived media first; retain summary/history.
48-hour demo retention; cleanup runs while backend is online.
Failed uploads retain local originals. No Supabase keys in browser/Replit UI.
Replacement API: scripts.restore_archive restores unexpired originals and index.
